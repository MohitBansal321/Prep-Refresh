# Fast & Slow Pointers — Worked Problems

Four fully worked, standalone, heavily commented C++17 solutions. Each file defines its own `ListNode` struct and helper functions, so any file can be compiled and run in isolation — you do not need `code.cpp` or any other file in this folder.

Compile and run any of them with:

```bash
g++ -std=c++17 -Wall path/to/file.cpp -o /tmp/out && /tmp/out
```

| # | Name | LeetCode # | Difficulty | One-line approach | Time / Space | File |
|---|------|-----------|------------|--------------------|---------------|------|
| 1 | Linked List Cycle | [141](https://leetcode.com/problems/linked-list-cycle/) | Easy | Slow/fast pointers meet if and only if a cycle exists (Floyd's Tortoise and Hare). | O(n) time, O(1) space | [01-linked-list-cycle.cpp](01-linked-list-cycle.cpp) |
| 2 | Middle of the Linked List | [876](https://leetcode.com/problems/middle-of-the-linked-list/) | Easy | Fast pointer reaches the end after traveling 2x the distance slow has — slow lands on the middle. | O(n) time, O(1) space | [02-middle-of-the-linked-list.cpp](02-middle-of-the-linked-list.cpp) |
| 3 | Happy Number | [202](https://leetcode.com/problems/happy-number/) | Easy | Treat "sum of squared digits" as the `next()` function over integers instead of `node->next`; detect a cycle the same way. | O(1) space (effectively O(log n) time per step until collision) | [03-happy-number.cpp](03-happy-number.cpp) |
| 4 | Palindrome Linked List | [234](https://leetcode.com/problems/palindrome-linked-list/) | Medium | Find the middle with Fast & Slow, reverse the second half in place (In-place Reversal), then compare from both ends. | O(n) time, O(1) space | [04-palindrome-linked-list.cpp](04-palindrome-linked-list.cpp) |

## Why these four

- **141** is the pattern in its purest form — no variation, just "does a cycle exist."
- **876** swaps the goal from "detect a cycle" to "find the midpoint without counting first," the second core use of the same two-speed idea.
- **202** proves the pattern is not actually about linked lists at all — it is about detecting a cycle in *any* sequence generated by repeatedly applying a function, here plain integers instead of `ListNode*`.
- **234** shows the pattern composing with its sibling, **In-place Reversal** (`../in-place-reversal/`) — a realistic example of two patterns stacking to solve one problem, which is how patterns actually get used once you're past the "one pattern per problem" stage of learning.

`exercises.md` (in the parent folder) gives you more problems to solve **without** a worked solution, for deliberate practice once you've studied these four.
